¿Qué es Open Source?

Open Source (código abierto) describe software cuyo código fuente se publica de forma abierta: cualquier persona puede leerlo, usarlo, modificarlo y redistribuirlo. No se trata solo de que el programa sea gratuito, lo central es la transparencia del código y la libertad para intervenir en él.

Este modelo se sostiene en licencias específicas (GPL, MIT, Apache) que definen legalmente qué se puede hacer con ese código, y en comunidades globales que colaboran de forma distribuida sin pertenecer a una misma empresa ni país.

Hoy el Open Source es la base de gran parte de la infraestructura tecnológica global: el servidor que aloja esta página, el navegador con el que la lees, el sistema operativo de tu teléfono, todo tiene raíces en proyectos abiertos. Además, cualquiera puede participar.

Las cuatro libertades

La Free Software Foundation resume el software libre en cuatro libertades, numeradas desde cero. Elige una para ver qué significa en la práctica.

0

Libertad 0: ejecutarlo

La libertad de ejecutar el programa como desees y con cualquier propósito: personal, educativo, empresarial o de investigación, sin pedir permiso a nadie.

EjemploInstalar Linux en tu casa, en una escuela o en un banco, sin pagar licencias por equipo ni pedir autorización.
1

Libertad 1: estudiarlo y cambiarlo

La libertad de estudiar cómo funciona el programa y de modificarlo para que haga lo que tú necesites. Para eso es indispensable tener acceso al código fuente.

EjemploAbrir el código de Firefox, entender cómo gestiona las pestañas y ajustarlo para tu propio uso.
2

Libertad 2: redistribuir copias

La libertad de redistribuir copias del programa para ayudar a otras personas, ya sea gratis o cobrando por el servicio de entregarlo o darle soporte.

EjemploGrabar una distro Linux en una USB y regalársela a un compañero de clase.
3

Libertad 3: compartir tus mejoras

La libertad de distribuir tus versiones modificadas a terceros, dándole a la comunidad la oportunidad de beneficiarse de tus cambios.

EjemploTu corrección de un error en un proyecto termina en la siguiente versión que usa todo el mundo.

La que te conviene

MIT

Permisiva · la más corta

Casi no pone condiciones: puedes usar el código incluso dentro de software cerrado, siempre que conserves el aviso de copyright y la licencia.

PermisivaCopyleft
  • Uso comercial
  • Modificar y redistribuir
  • Puede integrarse en software propietario
  • Debes conservar el aviso de la licencia
La usan: React, Node.js, Ruby on Rails
La que te conviene

Apache 2.0

Permisiva · con patentes

Parecida a MIT, pero añade una concesión expresa de patentes y pide que indiques los cambios que hiciste. Muy usada en proyectos con respaldo empresarial.

PermisivaCopyleft
  • Uso comercial
  • Incluye concesión de patentes
  • Compatible con software propietario
  • Debes indicar los cambios y conservar los avisos
La usan: Kubernetes, Android (AOSP), Apache HTTP Server
La que te conviene

GPL v3

Copyleft fuerte

Cualquiera puede usarla y modificarla, pero toda versión derivada que distribuyas debe seguir siendo libre y publicar su código fuente bajo la misma licencia.

PermisivaCopyleft
  • Uso comercial
  • Garantiza que el software siga siendo libre
  • Los derivados deben ser también GPL
  • Debes entregar el código fuente
La usan: GCC, GIMP, Bash

¿Open Source, libre, gratis o propietario?

Se confunden mucho. "Gratis" habla de precio; "open source" y "libre" hablan de qué puedes hacer con el código.

Open SourceSoftware libreFreewarePropietario
Código fuente visibleSíSíNoNo
Puedes modificarloSíSíNoNo
Puedes redistribuirloSíSíSegún el autorNo
Siempre es gratuitoNo siempreNo siempreSíDepende
EnfoqueCalidad y colaboración prácticaLibertad como derecho éticoUso sin costoControl del fabricante
EjemplosLinux, Firefox, PythonGNU Emacs, GIMP, LibreOfficeAdobe Reader, Google ChromeWindows, Photoshop

En la práctica casi todo el software libre es también open source y viceversa; la diferencia está sobre todo en el discurso: el software libre defiende la libertad como derecho, el open source subraya las ventajas prácticas de colaborar.

Así se contribuye a un proyecto abierto

Colaborar no requiere ser experto. Este es el camino típico en plataformas como GitHub:

1

Haz un fork

Copias el repositorio del proyecto a tu cuenta para trabajar sin riesgo. En Git: git clone.

2

Cambia el código

Corriges un error, agregas una función o mejoras la documentación en tu propia rama.

3

Abre un Pull Request

Propones tus cambios al proyecto original con una explicación clara de qué hiciste y por qué.

4

Revisión y merge

Las personas mantenedoras lo revisan, piden ajustes y, si todo va bien, lo integran al proyecto.
